# Block 12 最終 Demo — LinkedIn 系列發布規劃

> 本文件記錄 Block 12「最終 Demo」規劃從單篇整合影片改為多篇 LinkedIn 系列發布的
> 決策結果，供 progress-planner 執行 Issue 重整時參考。設計討論已走完
> feature-design-flow 階段 1–4 定案，此文件不重複討論過程，只記錄結論。

## 1. 決策背景

原規劃：Block 12 是單篇整合 Demo 影片，敘事弧線為「參數化控制 → RL 訓練 →
手臂執行」，對應 Issue #139（腳本規劃）、#140（錄製）、#141（剪輯）、
#145/#146（LinkedIn 草稿撰寫與潤稿），素材規劃為 #118（參數化擊球錄影）與
#227（RL 訓練 4 階段 checkpoint 對照回放＋reward 曲線＋工程真實感）。

改動原因：累積了較多新的實際工程結果，決定拆成多篇、每週發布一篇的
LinkedIn 系列，而非等到最後一次性發布整合影片。

## 2. 發布順序與節奏

篇6 → 篇7 → 篇8 → （視迴響）篇9，**每週發布一篇**。

## 4. 依賴關係

```
#118（既有，參數化擊球錄影）───────┐
                                    ├──> 篇6 新 Issue（文案＋發布，取代已關閉的 #119）
#115 / #116 / #235（既有功能）─────┘

docs/issue-181-strike-status-summary.md（架構轉向段落）─┐
scripts/verify_ur10e_cue_actuator.py（場景設定復用）────┼──> 篇7 新 Issue（錄製＋文案＋發布，一體）
assets/cue_actuator.usda（CueActuator prim）────────────┘
                                                             ⚠️ 明確不依賴 #230

#227（既有，RL 訓練 4 階段素材規劃）──────────────────> 篇8 新 Issue（文案＋發布）

篇6／篇7／篇8 發布後的迴響 ──────────────────────────> 篇9 佔位 Issue（內容待定）
```

發布順序即依賴順序：篇6 → 篇7 → 篇8 為素材各自獨立、可平行準備，但發布
節奏維持每週一篇、依序推進；篇9 的內容決策依賴前三篇發布後的迴響，因此
排在最後且暫不展開。
